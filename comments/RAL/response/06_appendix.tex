\subsection{Termination Conditions}
All conditions are checked at 60\,Hz in the environment frame; the table-top
height is $z_T=0.25$\,m.
\begin{enumerate}[label=(\alph*),leftmargin=2em,itemsep=2pt,topsep=3pt]
  \item \emph{Harmful collision:} We define a safety-clearance region above the
  table and monitor all arm--table contacts.  We trigger this termination when
  the palm or fingertips enter the clearance region, or when any arm link
  contacts the table.
  \item \emph{Object escape:} We define a permissible object workspace above
  the table that covers the intended manipulation region.  We trigger
  object-escape termination as soon as the object center leaves this space or
  falls below the table.
  \item \emph{Palm flipped:} The palm should face downward toward the object and
  table.  We trigger this termination when its downward direction differs from
  world-down by more than $90^\circ$, at which point the nominal grasp geometry
  is inverted.
  \item \emph{Hand too far:} We use the same permissible workspace as in (b)
  and trigger this termination when the palm link leaves it, indicating that
  the hand has moved too far during exploration.
  \item \emph{Timeout:} We terminate the episode when the time index reaches
  the maximum episode horizon, $t\geq T_{\max}$.
\end{enumerate}
Expanding the termination rule used in the main paper gives
\[
\mathbb I_{\rm term}(s_t,t)
=\mathbb I_{\rm coll}(s_t)\lor\mathbb I_{\rm obj}(s_t)
 \lor\mathbb I_{\rm flip}(s_t)\lor\mathbb I_{\rm hf}(s_t)
 \lor\mathbb I_{\rm timeout}.
\]
To avoid conflicts between simultaneous termination conditions, we assign the
event label using the following descending severity priority:
$\text{harmful collision}\succ\text{object escape}\succ\text{palm flipped}
\succ\text{hand too far}\succ\text{timeout}$.

\subsection{Output Processing and Threshold Updates}
The requested machine-readable output is a top-level JSON object with the
following schema:
\begin{verbatim}
{
  "l2_threshold": <number>, "success_threshold": <number>,
  "confidence": <number>, "reason": <string>
}
\end{verbatim}
The two returned thresholds are absolute candidates. Each candidate is clipped
to a fixed range around its initial value and then exponentially smoothed with
the previously applied threshold. For $x\in\{\delta,Q\}$,
\[
\bar\tau_x^{(k)}=\operatorname{clip}\!\left(
\hat\tau_x^{(k)},c_x^{\min}\tau_x^{(0)},
c_x^{\max}\tau_x^{(0)}\right),\qquad
\tau_x^{(k+1)}=(1-\alpha)\tau_x^{(k)}+\alpha\bar\tau_x^{(k)}.
\]
We use $\alpha=0.1$ and $(c_x^{\min},c_x^{\max})=(0.5,1.5)$ for both
thresholds. The updated values are applied from the next control step through
the intervention gate
$\lVert a_t^S-a_t^T\rVert_2>\tau_\delta\ \lor
\hat Q_{\mathrm{succ}}(s_t,a_t^S)<\tau_Q$; lowering $\tau_\delta$ or raising
$\tau_Q$ increases teacher intervention. The \texttt{confidence} and
\texttt{reason} fields are logged for diagnostics and do not alter the update.
This adaptation is used only during simulation distillation; physical
deployment uses the frozen RGB student alone.

If a VLM request fails or its output cannot be parsed, the controller retains
the previously applied thresholds and tries again at the next scheduled update.
None of the reported trials encountered a condition that activated this
fallback.

\subsection{Bellman Critic Evaluation}
We conduct an independent evaluation of the Bellman critic under the rollout
setting of ablation~(b), in which the student policy remains in control for the
entire episode and the teacher never intervenes. The critic runs in parallel as
a passive evaluator: it predicts the safe-lift-success value of each proposed
student state--action pair, but its prediction does not alter the executed
action or trigger teacher takeover. Consequently, unsafe terminal events remain
observable, allowing us to measure whether the critic signaled low predicted
safe-lift success before each observed unsafe termination.

An unsafe episode is counted as detected if the predicted safe-lift-success
value falls below the deployed threshold at least once before the unsafe
termination; otherwise, it is counted as a false negative. A safe-success
episode is counted as a false alarm if the critic falls below the threshold at
least once. For detected unsafe episodes, warning time is measured from the
first threshold crossing to the unsafe termination.

\subsection{Operating-Point Analysis of the Bellman Critic}
The Bellman critic predicts the joint acceptable outcome of successful lifting
without an unsafe event. To make the behavior of this joint target transparent,
we partition the independently evaluated episodes into three mutually exclusive
outcomes: safe lift success, safe lift failure, and unsafe termination. A safe
lift failure reaches the episode horizon without satisfying the lift criterion
and without triggering any of the four unsafe termination conditions. For each
outcome, we report how often the critic falls below the deployed intervention
threshold before the episode ends.
