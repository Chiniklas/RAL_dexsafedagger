\subsection{Termination Conditions}
All conditions are checked at 60\,Hz in the environment frame; the table-top
height is $z_T=0.25$\,m.
\begin{enumerate}[label=(\alph*),leftmargin=2em,itemsep=2pt,topsep=3pt]
  \item \emph{Harmful collision:} We define a safety-clearance region above the
  table and monitor all arm--table contacts.  We trigger this termination when
  the palm or fingertips enter the clearance region, or when any arm link
  contacts the table.
  \item \emph{Object escape:} We define a permissible object workspace above
  the table that covers the intended manipulation region.  We trigger
  object-escape termination as soon as the object center leaves this space or
  falls below the table.
  \item \emph{Palm flipped:} The palm should face downward toward the object and
  table.  We trigger this termination when its downward direction differs from
  world-down by more than $90^\circ$, at which point the nominal grasp geometry
  is inverted.
  \item \emph{Hand too far:} We use the same permissible workspace as in (b)
  and trigger this termination when the palm link leaves it, indicating that
  the hand has moved too far during exploration.
  \item \emph{Timeout:} We terminate the episode when the time index reaches
  the maximum episode horizon, $t\geq T_{\max}$.
\end{enumerate}
Expanding the termination rule used in the main paper gives
\[
\mathbb I_{\rm term}(s_t,t)
=\mathbb I_{\rm coll}(s_t)\lor\mathbb I_{\rm obj}(s_t)
 \lor\mathbb I_{\rm flip}(s_t)\lor\mathbb I_{\rm hf}(s_t)
 \lor\mathbb I_{\rm timeout}.
\]
To avoid conflicts between simultaneous termination conditions, we assign the
event label using the following descending severity priority:
$\text{harmful collision}\succ\text{object escape}\succ\text{palm flipped}
\succ\text{hand too far}\succ\text{timeout}$.

\subsection{Model and Input Configuration}
We used the OpenAI GPT-5.5 multimodal model through the Chat Completions endpoint
(\texttt{/v1/chat/completions}, \texttt{model="gpt-5.5"}). Each request set
\texttt{stream=false} and \texttt{max\_completion\_tokens=1024}; no temperature
or reasoning-effort parameter was sent, so the provider defaults applied. The
model received the textual rollout statistics above and up to eight RGB images,
encoded as downsampled JPEG data URLs with high visual detail. We issued the
first VLM query after 2{,}000 online distillation steps and subsequently queried
it every 10{,}000 steps, resulting in 10 calls over the 100{,}000-step run. The
archived API reports, which were generated with the previous low-detail image
setting, record 30{,}641 prompt tokens and 4{,}841 completion tokens, or 35{,}482
tokens in total.

\subsection{Output Processing and Threshold Updates}
The requested machine-readable output is a top-level JSON object with the
following schema:
\begin{verbatim}
{
  "l2_threshold": <number>, "success_threshold": <number>,
  "confidence": <number>, "reason": <string>
}
\end{verbatim}
The implementation first attempts to parse the complete assistant response as
JSON. If that fails, it parses the substring from the first opening brace to the
last closing brace, which permits recovery from a surrounding Markdown code
fence or brief prefatory text. Only a JSON object is accepted. The two threshold
fields are converted to floating-point values independently; a missing or
non-convertible field leaves that threshold at its current value, and
unrecognized fields are ignored. The \texttt{confidence} and \texttt{reason}
fields are recorded for diagnostics but neither changes nor vetoes the
controller update.

The returned thresholds are interpreted as absolute candidates, not direct
intervention decisions. For each $x\in\{\delta,Q\}$, the candidate is clipped
and exponentially smoothed as
\[
\bar\tau_x^{(k)}=\operatorname{clip}\!\left(
\hat\tau_x^{(k)},c_x^{\min}\tau_x^{(0)},
c_x^{\max}\tau_x^{(0)}\right),\qquad
\tau_x^{(k+1)}=(1-\alpha)\tau_x^{(k)}+\alpha\bar\tau_x^{(k)}.
\]
We used $\alpha=0.1$ and $(c_x^{\min},c_x^{\max})=(0.5,1.5)$ for both
thresholds. In the archived run, $\tau_\delta^{(0)}=3.0$, yielding the allowed
range $[1.5,4.5]$. Warm-start calibration set
$\tau_Q^{(0)}=0.7081624$, yielding the implemented range
$[0.3540812,1.0622436]$. For example, the first recommendation
$\hat\tau_\delta=3.2$ produced the applied value
$0.9(3.0)+0.1(3.2)=3.02$.

In \texttt{active} mode, the filtered disagreement threshold becomes the
controller's $\tau_\delta$, and the filtered success threshold is assigned to
the Bellman critic's intervention threshold. They affect the next control step
through the strict gate
$\lVert a_t^S-a_t^T\rVert_2>\tau_\delta\ \lor
\hat Q_{\mathrm{succ}}(s_t,a_t^S)<\tau_Q$; lowering $\tau_\delta$ or raising
$\tau_Q$ therefore increases teacher intervention. In \texttt{shadow} mode,
the same outputs are logged without changing either threshold. The first query
was made at online distillation step 2{,}000 and later queries every 10{,}000
steps, at steps 2{,}000, 12{,}000, $\ldots$, 92{,}000.

The deterministic fallback is to retain the last applied thresholds. This
occurs when the API key is unavailable, the request times out or fails, the API
response is malformed, or no JSON object can be parsed. If only one threshold
field is missing or non-convertible, that coordinate is retained while a valid
coordinate may still be clipped and updated. A failed attempt is logged and is
not retried immediately; the next attempt occurs at the next scheduled update.
Finally, the VLM and this adaptation mechanism are used only during
simulation-based online distillation. There is no real-world student training,
and during physical deployment the RGB student acts without the VLM,
privileged teacher, Bellman critic, or threshold adaptation.
